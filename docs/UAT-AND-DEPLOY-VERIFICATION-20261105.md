# RMUTI KKC — สรุปชุดทดสอบรอบพัฒนาและ UAT ผู้สมัคร–แอดมิน (5 พ.ย. 2569)

## ทดสอบอัตโนมัติใน GitHub CI
- `npm ci`, `npm run lint`, `npm test`, `npm run build` ทุก PR ก่อน merge
- เพิ่ม `tests/notification-inbox.test.ts`: การจัดข้อความยังไม่อ่าน, เรียงลำดับใหม่ก่อน และไม่แก้ข้อมูล cache
- หน้า Deploy เรียก `scripts/smoke-pages.mjs` หลัง GitHub Pages deployment สำเร็จ เพื่อยืนยัน HTTP 200, #root และ JavaScript bundle โหลดได้จริง (ไม่ใช้บัญชีจริง ไม่อ่านข้อมูลผู้สมัคร)
- `npm run test:api` เป็นการทดสอบ API แบบไม่เขียนข้อมูล เรียกด้วยสิทธิ์/เครือข่ายที่ทีมดูแลอนุญาต

## Test matrix ที่ต้องทำกับบัญชีทดสอบที่ได้รับอนุญาต (ยังไม่ถือว่าผ่านจริง)
| หมวด | กรณีทดสอบ | ผลที่คาดหวัง |
|---|---|---|
| สมัคร/เข้าสู่ระบบ | สมัครสมาชิก, เข้าระบบ, ออกจากระบบ, reset password | เข้าถึงข้อมูลบัญชีตัวเองเท่านั้น |
| แบบร่าง/ส่งสมัคร | อัปโหลดรูป PDF และสลิป, ส่งใบสมัคร, ทดสอบออกจากระบบกลางทาง | บันทึกครบตามเงื่อนไข ไม่สร้างใบสมัคร/คิวซ้ำ |
| การตรวจเอกสาร | แอดมินขอแก้ไขพร้อมเหตุผลและกำหนด | ผู้สมัครเห็นข้อความ/วันกำหนด/ปุ่มแก้ไขในเว็บ |
| ผลคุณสมบัติ | ผ่าน, ไม่ผ่าน, ประวัติแจ้งแก้ไข | สถานะและประวัติตรงกัน ผู้สมัคร B ไม่เห็นของ A |
| กำหนดสอบ | เผยแพร่วันสอบ/ห้องสอบใหม่สำหรับตำแหน่งทดสอบ | ผู้มีสิทธิในตำแหน่งเดียวกันได้รับ notification |
| เปลี่ยนห้องสอบ | เปลี่ยนเฉพาะสถานที่สอบหลังเผยแพร่ | แจ้งห้องเดิม/ห้องใหม่ครั้งเดียวต่อเหตุการณ์ |
| บัตรสอบ | ออกบัตร, ดาวน์โหลด PDF, เพิกถอน | แจ้งเหตุการณ์, บัตรเก่าที่เพิกถอนใช้ไม่ได้ |
| ประกาศผล | เผยแพร่ผลสอบผ่านตำแหน่งทดสอบ | แจ้งผู้สมัครในประกาศเท่านั้น ไม่แจ้งคนอื่น |
| ศูนย์แจ้งเตือน | กรองยังไม่อ่าน/ทั้งหมด, อ่านทั้งหมด, ดูรายละเอียด | จำนวนลดและข้อความเก่าไม่ถูกลบ |
| เอกสาร Drive | เปิดไฟล์ของเจ้าของและเจ้าหน้าที่, ลองผู้สมัครคนอื่นเปิด | เปิดได้เฉพาะผู้มีสิทธิ |
| โหลดและมือถือ | จอ 360px, 768px, 1920px, สัญญาณช้า | อ่านและทำงานได้ ไม่มีปุ่มทับข้อความ |
| Load / concurrent | ส่งใบสมัครเดียวกันพร้อมกัน 2 sessions และตำแหน่ง quota=1 | ไม่มี duplicate และไม่รับเกินอัตรา |
| ออกจากระบบ | session หมดอายุระหว่างเปิดใบสมัคร | ไม่เห็นข้อมูลบุคคลหลัง session หมดอายุ |
| หลัง Deploy | เปิดหน้าเว็บผ่าน GitHub Pages บน browser จริง | โหลด asset/version ถูกต้อง |

## ข้อห้ามใน production
- ห้ามกดเปลี่ยนสถานะ/ออกบัตร/เผยแพร่ประกาศจริงเพื่อทดสอบ
- ทดสอบ workflow เขียนข้อมูลใน Supabase *test project* ที่แยกจาก production เท่านั้น
- ห้ามลบข้อมูลผู้สมัครหรือไฟล์ต้นฉบับเพื่อตรวจว่ากู้คืนได้
- คำว่า "GitHub CI ผ่าน" ไม่เท่ากับ "ทดสอบการใช้งานจริงทุกขั้นตอนผ่าน" และ HTTP smoke ไม่ใช่การยืนยันข้อมูลส่วนบุคคล/สิทธิ์

## ก่อนเปิดรับสมัครรอบใหม่
ให้ทีมงานบันทึกผล UAT รายข้อพร้อมผู้ทดสอบ วันที่ ข้อผิดพลาด และหลักฐานภาพที่ไม่มีข้อมูลส่วนบุคคล; ให้ IT รับรองผล Backup Restore, การตั้ง Auth leaked-password protection, และการทดสอบสองบัญชีใน browser จริง
