# ระบบแจ้งเตือนผู้สมัครภายในเว็บไซต์ RMUTI KKC

ยกเลิกช่องทางส่งอีเมลแจ้งเตือนผู้สมัครตามคำสั่งเจ้าของระบบแล้ว ผู้สมัครติดตามความคืบหน้าได้ที่ **ใบสมัครของฉัน** โดยใช้ฐานข้อมูลและการแจ้งเตือนภายในเว็บไซต์ที่มีอยู่เดิม

## ส่วนที่เห็นในเว็บ

- แถบกระดิ่ง "แจ้งเตือน" พร้อมจำนวนข้อความที่ยังไม่อ่านในส่วนหัวเว็บไซต์ (เฉพาะบัญชีผู้สมัคร)
- หน้า Dashboard แสดง "ศูนย์แจ้งเตือนสถานะใบสมัคร" และการ์ดสถานะแยกสีตามแต่ละใบสมัคร
- รายการสถานะ: รับใบสมัครแล้ว, อยู่ระหว่างตรวจ, ต้องแก้ไข, ผ่านคุณสมบัติ, ไม่ผ่านคุณสมบัติ, ถอนใบสมัคร
- สถานะต้องแก้ไข: แสดงข้อความเจ้าหน้าที่, วันหมดเขต, ปุ่มแก้ไขใบสมัคร
- สถานะไม่ผ่าน: แสดงข้อความเหตุผลจากเจ้าหน้าที่ (หากมี)
- สถานะผ่าน: ชี้แจงให้ติดตามกำหนดสอบและบัตรสอบ และมีทางเข้าสู่รายละเอียดใบสมัคร
- รายการแจ้งเตือนเดิมยังคงมีประวัติและสามารถกดอ่านแล้ว โดยอัปเดตข้อมูลจากเซิร์ฟเวอร์ทุก 30 วินาที
- หน้าใบสมัครแสดงสถานะล่าสุดด้านบน พร้อมข้อความสำคัญ และประวัติสถานะเดิมยังอยู่

## การปิดการส่งอีเมล

- Migration `20261105111500_retire_applicant_email.sql` ตั้งค่า `applicant_mail.enabled=false`, ยกเลิกจุดสร้างคิวทางอีเมลแบบไม่ลบข้อมูล และยกเลิก RPC เปิดส่ง
- Edge Function `applicant-email-worker` ตอบ 410 ตลอดเวลา ไม่เข้าถึงบริการส่งเมล
- GitHub Actions `applicant-email-worker.yml` ถูกนำออก
- เมนูและคิวอีเมลในหน้า Admin Settings ถูกนำออก
- ไม่ลบข้อมูลผู้สมัคร, บัตรสอบ, ประวัติสถานะ, หรือประวัติการแจ้งเตือนในเว็บไซต์

## การทดสอบหลังเผยแพร่

1. เข้าบัญชีผู้สมัครทดสอบที่มีใบสมัครยืนยันส่งแล้ว เปิด Dashboard ตรวจว่ามีสถานะบนการ์ดและในหน้ารายละเอียดตรงกับฐานข้อมูล
2. เปลี่ยนสถานะในบัญชีเจ้าหน้าที่ทดสอบ แล้วตรวจว่าผู้สมัครเห็นหลังรีเฟรชหรือรอการอัปเดตไม่เกินรอบ 30 วินาที
3. ใช้ใบสมัครทดสอบที่มีสถานะต้องแก้ไข ตรวจข้อความจากเจ้าหน้าที่ วันหมดเขต และปุ่มแก้ไข
4. ตรวจว่าแถบกระดิ่งแสดงจำนวนยังไม่อ่าน กดอ่านแล้วจำนวนลดลงหลังรีเฟรชข้อมูล
5. ตรวจว่าไม่มีคิว `email_outbox` เพิ่มจากเหตุการณ์ใหม่ และ worker ตอบ 410 แม้ถูกเรียก
6. ตรวจการดูประวัติข้อความเดิมในหน้าใบสมัคร และตรวจการเปิดบัตรสอบที่ออกแล้ว

ข้อความบนเว็บไซต์ **ไม่ใช่** การส่ง push notification ไปยังอุปกรณ์ภายนอก ผู้สมัครต้องเข้าสู่เว็บไซต์เพื่ออ่าน
